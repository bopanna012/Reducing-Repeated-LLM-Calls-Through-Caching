Background & Research Questions
LLM called for every request — even exact duplicates
Paraphrased, reworded queries dominate real usage
Caching is proven in web engineering, underused in AI
Redundant inference has a real latency, cost and compute footprint
Problem Overview
LLM-backed FAQ systems routinely re-answer questions that only differ in wording — paying full inference cost and latency for a query the system has, in effect, already seen. This project puts a two-stage cache (exact match, then FAISS semantic search) in front of a local Llama 3 model and measures how much redundant inference it removes.
Research Questions
1
What proportion of requests can be served from cache instead of the LLM?
2
How much do caching strategies reduce model calls, latency, and cost?
3
How does semantic caching compare with exact-match for answer quality and safe reuse?

2
Exact-match cache checked first (normalized string compare)
3
Miss → encoded with all-MiniLM-L6-v2 into a 384-dim vector
4
FAISS flat index returns nearest neighbor + cosine score
5
Score ≥ 0.50 → reuse cached answer; else call Llama 3 & cache it

Borderline Failure Case
1 of 81 semantic hits (1.2%) is an incorrect reuse despite clearing the 0.50 similarity gate — string similarity and topic overlap both stayed below the safe-reuse rubric. Safety verdict: consider raising the threshold for production use.

Discussion & Conclusion
Why the hit rate is so high (90.5%)
FAQ questions cluster into a small set of underlying intents; template paraphrasing stays semantically close to the cached originals, so a 0.50 cosine threshold catches nearly all of them.
Semantic similarity ≠ semantic correctness
1 of 81 semantic hits (1.2%) reused a factually wrong answer despite clearing the similarity gate — embedding distance is a proxy for meaning, not a guarantee of it.
When do we need semantic caching?
Exact-match alone is close to useless once users reword questions (5.3% hit rate); semantic caching is what actually absorbs paraphrase traffic in a live FAQ system.
Limitations
Template paraphrases, a small 115-entry FAQ set, one embedding model, and local inference — results may shift with real user phrasing or a larger corpus.
Conclusion — Key Research Findings
RQ1
90.5% of paraphrased queries are served from cache without touching the LLM.
RQ2
Caching cuts LLM calls 91%, latency 11×, and estimated cost 91% vs. calling the model every time.
RQ3
Semantic-cache answers match gold 89.5% of the time — far above exact-match's 5.3% — with one flagged unsafe reuse in 81 hits.
